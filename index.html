The collective story

These are not side projects in a pile. They are one sequence:

  • 2025 — ship software with models in the loop. Ledger, CRM, SDS parsing, meetings, DMAIC. I learned what “done” means when an LLM is helping write the system.
  • Early 2026 — ship operator products. MobPay, DefiantMob, MobHub, BeltBrain, DHG. Live desks with auth, money movement, ledgers, and planning — not demos.
  • Mid 2026 — the accidental agent platform. Inside MobPay I built MobDev (task → brief) and a multi-vendor panel arena. Every rule was still prose. The model still got a vote.
  • Jul 2026 onward — extract the control plane. Atlas Harness (formerly codeharness) turns that prose into typed policy, lanes, done-gates, provenance, recovery, and evaluation. Same job an enterprise needs: agents that act, under law.

An Agentic AI Architect role is that last step, at company scale: reference designs, safety standards, and an operating model other teams can run. I already designed and operated the personal version under real load.

Reference architecture I already run

What I would put on a whiteboard in week one. I built each box because the desk failed without it.

1. IntentBusiness job, not a chat. Standing authorization. Scoped goal.
2. OrchestrationLanes. Max fan-out. Named roles. No lateral command.
3. ToolsFunction interfaces as subprocesses / APIs. Model does not own credentials.
4. GatesDone-criteria. Human-in-the-loop. Fail closed. Escalate / redact.
5. ProofProvenance, receipts, sealed evals, kill / recovery, cost awareness.

Enterprise translation: multi-agent pattern → tool/function layer → HITL + policy → RAG/memory as provenance → eval, telemetry, incident response. I used coding CLIs as the first “enterprise system.” The pattern is the same for SAP or Salesforce: the agent proposes an action; the harness decides whether it may fire.

Work, sold as one portfolio

Atlas Harness — control plane for agents

Jul 2026 → present · TypeScript / Python · formerly codeharness · 406 spine commits

A policy and recovery layer over coding agents. Not a model. Not a chat UI. The product is the desk other agents must obey: who may act, when work is done, which lane they are in, and what evidence remains.

  • Multi-agent pattern: steward, heartbeat, workers, kill-squad, historian. Topology is law, not a prompt suggestion.
  • Tool interfaces: Claude, Codex, and Grok as engines on existing subscriptions — orchestrate, don’t rebuild the runtime.
  • Human oversight: typed done-gates. The model cannot mark complete. Interrupt and resume are first-class.
  • Safety: redact, escalate, authority boundaries, channel firewalls, participant controls, emergency court (Love / L2).
  • Eval & ops: sealed exams, evidence ledgers, receipts, recovery paths, cost as an architectural constraint (~subscription vs raw-token blowup).

How I would do the job

Standards

Reference design first: lanes, tool contracts, gate policy, memory/provenance, env segregation. Teams don’t get a free-form agent. They get a pattern they can fail closed inside.

Safety

Prompt injection and over-reach are architecture bugs. Redact, classify, deny-by-default, human gate on side effects. Partner with Security/Legal on data classes — I already treat “the model asked” as non-authorization.

Eval & FinOps

Task-based evals before widen. Trace every action. Kill and recover. Prefer orchestrating paid runtimes over inventing a new one. Measure latency and cost as SLAs, not afterthoughts.
